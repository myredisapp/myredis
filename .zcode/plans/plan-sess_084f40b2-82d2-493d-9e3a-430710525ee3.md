## 目标

Release 里的安装包名统一成 `myredis-<tag>-<platform>.<ext>`，macOS 从 arm64/x64 两个包合并为一个 universal 包：

| 平台 | 现在 | 改后 |
| --- | --- | --- |
| macOS（arm64） | `麦地缓存_0.2.0_aarch64.dmg` | `myredis-v0.2.0-macos-universal.dmg`（合二为一） |
| macOS（x64） | `麦地缓存_0.2.0_x64.dmg` | — |
| Linux | `maidi-cache_0.2.0_amd64.deb` / `.AppImage` | `myredis-v0.2.0-linux-x64.deb` / `myredis-v0.2.0-linux-x64.AppImage` |
| Windows | `麦地缓存_0.2.0_x64-setup.exe` / `麦地缓存_0.2.0_x64_zh-CN.msi` | `myredis-v0.2.0-windows-x64.exe` / `myredis-v0.2.0-windows-x64.msi` |

只改发布产物的文件名，`productName` 保持不动 —— 应用名、窗口标题、安装目录仍是「麦地缓存」，本地 `tauri build` 的输出名也不变。

## 改动

### 1. `.github/workflows/release.yml`

**a. matrix 合并 macOS 两项**，并新增 `rust-targets` 字段承载「一个 target 可能要装多个 rust target」：

```yaml
- os: macos-latest
  label: macos-universal
  target: universal-apple-darwin
  rust-targets: aarch64-apple-darwin,x86_64-apple-darwin
  bundles: app,dmg
- os: ubuntu-22.04   # 保留现有注释：22.04 打包才有更低的 glibc 依赖
  label: linux-x64
  target: x86_64-unknown-linux-gnu
  rust-targets: x86_64-unknown-linux-gnu
  bundles: deb,appimage
- os: windows-latest
  label: windows-x64
  target: x86_64-pc-windows-msvc
  rust-targets: x86_64-pc-windows-msvc
  bundles: nsis,msi
```

- 安装 rust target 这步改成 `targets: ${{ matrix.rust-targets }}`（universal 需要 arm64 + x64 两个 target 都装上，tauri 靠 lipo 合成）。`rust-cache` 的 `key` 仍用 `matrix.target`，无需改。
- 构建命令不变：`tauri build --target universal-apple-darwin --bundles "app,dmg"`，产物路径变成 `target/universal-apple-darwin/release/bundle/dmg/...`，正好被现有 `src-tauri/target/${{ matrix.target }}/...` 覆盖。

**b. 新增改名步骤**（放在「构建并打包」之后、「上传安装包」之前）：

```yaml
      - name: 规范化安装包文件名
        shell: bash
        run: node .github/scripts/rename-artifacts.mjs "src-tauri/target/${{ matrix.target }}/release/bundle" "${{ github.ref_name }}" "${{ matrix.label }}"
```

显式写 `shell: bash`（Windows runner 默认 PowerShell，路径与引号处理不同），并保持单行避免续行符在 PowerShell 下失效。

**c. 上传路径收紧**为 `src-tauri/target/${{ matrix.target }}/release/bundle/*/myredis-*`，替掉现在那五行按扩展名罗列的 glob。好处：改名失败时 `if-no-files-found: error` 会直接把流水线卡住（现在的 glob 在改名失败时仍会匹配到中文原名，静默放过）。

### 2. 新增 `.github/scripts/rename-artifacts.mjs`

用法 `node rename-artifacts.mjs <bundleDir> <tag> <platform>`。

- 只扫 `bundle/<一层子目录>/<文件>`（`dmg` / `deb` / `appimage` / `nsis` / `msi`），**不递归** —— 避免误抓 tauri 在 bundle 下层留下的中间产物。
- 扩展名白名单 `['.dmg', '.deb', '.AppImage', '.msi', '.exe']`，扩展名原有大小写保留（`.AppImage` 的写法不能变，否则语义丢失）。
- 校验：`bundleDir` 必须存在；每个扩展名最多一个文件（同一扩展名出现两个即视为命名冲突，直接失败）；总数为零则失败并报错；tag 只允许 `[0-9A-Za-z.+-]`，防非法文件名字符。
- 逐个 `rename` 并打印 `旧名 → 新名`，便于在 CI 日志里核对。
- 用 Node 而非内联 shell，是因为要跨 bash / PowerShell 两种 runner，且能本地直接跑测试 —— 与已有的 `set-version.mjs` 保持一致。

预期各平台产出：macOS 1 个（dmg）、Linux 2 个（deb + AppImage）、Windows 2 个（exe + msi），扩展名互不冲突，所以不会撞名。

### 3. `DEVELOPMENT.md` §8 补一节

新增 §8.5「Release 安装包命名」，说明：本地 `tauri build` 仍按 `productName` 命名（§8.1 / §8.4 的描述继续有效），只有 CI 在上传前统一改名为 `myredis-<tag>-<platform>.<ext>`；以及 macOS 为什么合并成 universal（用户只下一个包，代价是 x64 多编译一遍）。

## 验证

1. `node --check` 语法检查新脚本；用 Python/Node 解析 `release.yml` 确认 YAML 合法。
2. 把现有 `src-tauri/target/aarch64-apple-darwin/release/bundle` 拷一份到 `/tmp`，实跑改名脚本，确认中文名 dmg 被正确改成 `myredis-v9.9.9-macos-universal.dmg`，并验证重复扩展名、空目录、非法 tag 三种情况都会报错退出。
3. 不动本地 `src-tauri/target` 里的真实产物。

真正的端到端验证需要打 tag 触发流水线（我这边不会自己推 tag）；如果你要的话，实现完我可以顺手在本地跑一次 `npm install -g @tauri-apps/cli@2.11.3 && tauri build --target aarch64-apple-darwin --bundles dmg` 确认改名步骤接得上真实产物。
